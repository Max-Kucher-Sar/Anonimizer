# Anonymizer

Локальный сервис анонимизации персональных данных (PII) — **текст и файлы**.
Рассчитан на работу **без GPU**, на обычном CPU.

Compose запускает API, локальную Ollama и загрузку модели в сохраняемый том.
По умолчанию используется CPU; HTTPS-прокси подключается профилем `tls`.

Изображения не поддерживаются: ни детекции лиц, ни OCR, ни Vision-LLM. Вместо
этого `/api/v1/anonymize/file` принимает готовые документы и правит их на
месте — в xlsx меняются значения ячеек, в docx и pptx — текст абзацев.

**PDF не поддерживается.** Заглушку в готовый PDF не вставить: текст лежит в
content stream и не перезаписывается, а пересборка документа ломает вёрстку и
шрифты. Поэтому `.pdf` отклоняется с `400`. Сканы и PDF разбирайте во внешнем
инструменте и заливайте результат как `.txt`.

По умолчанию текст обрабатывается регулярными выражениями с проверкой
контрольных сумм, spaCy и узкими контекстными правилами. Дополнительно можно
включить локальную LLM через Ollama для проверки ФИО, организаций и мест.
OCR и Vision не используются. Ничего не скачивается при старте.

## Локальная проверка на Windows и Ollama

Docker для разработки не требуется. В командах ниже окружение называется
`venv`; если у вас `.venv`, замените имя каталога.

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\venv\Scripts\python.exe -m spacy download ru_core_news_sm
.\venv\Scripts\python.exe -m pytest -q

# Ollama должен быть установлен и запущен отдельно
ollama pull qwen2.5:7b
$env:ANON_OLLAMA_ENABLED = 'true'
.\venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Интерфейс API: `http://127.0.0.1:8000/docs`. Для отключения LLM задайте
`$env:ANON_OLLAMA_ENABLED = 'false'` и перезапустите API. `.env` автоматически
не читается при нативном запуске: используйте переменные PowerShell.

Ollama проверяет кандидатов spaCy и независимо ищет пропущенные имена в
перекрывающихся фрагментах исходного текста. Она не может отменять находки
regex или правила для подписей. Модель возвращает решения и точные подстроки
по JSON-схеме, а смещения и замены вычисляет Python. Неполный или некорректный
ответ (после двух попыток исправления), таймаут или недоступность модели
возвращают HTTP 503 без выдачи файла.
Правила для подписей с инициалами и обозначений `Ду=16`, `DN150`, `PN16`
работают также при отключённой Ollama.

Дополнительные настройки: `ANON_OLLAMA_URL` (по умолчанию
`http://127.0.0.1:11434`, разрешены только локальные адреса),
`ANON_OLLAMA_MODEL` (`qwen2.5:7b`), `ANON_OLLAMA_TIMEOUT_SECONDS`
(`180`, на один фрагмент), `ANON_OLLAMA_CHUNK_CHARS` (`2400`). Модель
скачивается заранее; не используйте облачные модели. Для отключения облачных
функций самой Ollama задайте `OLLAMA_NO_CLOUD=1` в окружении её процесса и
перезапустите Ollama. В Compose Ollama включена по умолчанию, API использует
`http://ollama:11434` с `ANON_OLLAMA_ALLOW_CONTAINER_HOST=true`. Этот флаг
разрешает только фиксированное имя Docker-сервиса, не произвольный сервер.

LLM может ошибаться; качество и время нужно оценивать на реальных документах.
В проверке `example.docx` маленькая `qwen3:4b-instruct` оставила много ложных
ФИО, поэтому по умолчанию выбрана уже установленная `qwen2.5:7b`.
Модель можно заменить через `ANON_OLLAMA_MODEL`, но уменьшение размера
не гарантирует достаточную точность.

## Архитектура

### Текст

```
                     ┌─────────────────────────────────────────┐
POST /anonymize/text │                                         │
  ────────────────►  │  1. RegexDetector                       │
                     │     ИНН, СНИЛС, паспорт, карты, IBAN,   │
                     │     email, телефон, счёт, бик, крипта   │
                     │     + проверка контрольных сумм        │
                     │                    │                    │
                     │                    ▼                    │
                     │  2. Presidio (spaCy ru_core_news_sm)    │
                     │     PERSON / ORG / LOCATION / DATE      │
                     │                    │                    │
                     │                    ▼                    │
                     │  3. resolve_overlaps → redact           │
                     └─────────────────────────────────────────┘
```

Почему regex и spaCy остаются основой:

- **Номера с невалидной контрольной суммой отсекает regex.** Модель их бы
  «заметила», но вслепую: она не умеет считать контрольные суммы ИНН.
- **Детерминированный детектор повторяем.** Один и тот же файл даёт один и тот
  же результат, а на CPU это ещё и на порядок быстрее вызова модели.
- **Договоры, заявки и счета — это структурные поля.** ИНН, СНИЛС, паспорт,
  карта, расчётный счёт, телефон, e-mail: то, что regex и spaCy находят
  целиком, без эскалации.

Чем пришлось заплатить: `MEDICAL` умел искать прежний LLM-детектор, поэтому его больше
нет в списке сущностей. С возрастом, адресами и свободными формулировками в
родном виде сервис не работает — сначала приведите текст к структурным полям.

### Файлы

```
POST /anonymize/file
  ────────────────►  ┌──────────────────────────────────────────┐
                     │ 1. Разбор по формату                      │
                     │   txt/md/log/csv/tsv/json — текст целиком │
                     │   docx/xlsx/pptx — абзацы, ячейки, слайды │
                     │                    │                     │
                     │                    ▼                     │
                     │ 2. Склейка кусков переводом строки        │
                     │   spaCy видит связный контекст:           │
                     │   «Иванов\nИван\nИванович» → одна ФИО     │
                     │                    │                     │
                     │                    ▼                     │
                     │ 3. Тот же текстовый пайплайн (1–4 выше)  │
                     │   ровно один вызов на весь документ      │
                     │                    │                     │
                     │                    ▼                     │
                     │ 4. Разбор результата обратно по смещениям │
                     │   находка применяется к каждому           │
                     │   пересекаемому куску                     │
                     │                    │                     │
                     │                    ▼                     │
                     │ 5. Запись в исходный формат               │
                     │   docx/xlsx/pptx — текст на место        │
                     └──────────────────────────────────────────┘
```

Почему так:

- **Куски склеиваются переводом строки, а не маркерами.** Проверено: искусственные
  метки вида `<|SEGaab|>` разрывают фразу, и с ними ФИО не находится вообще.
  Обратная сборка идёт по смещениям находок — их и так возвращает пайплайн.
- **Замена делается по тексту каждого куска, а не общей строкой.** Длины
  заглушек не влияют на соседние куски, а ФИО, разложенное на три абзаца,
  закрывается во всех трёх.
- **Один вызов пайплайна на документ, а не по ячейке.** ФИО в xlsx часто
  разнесено по трём соседним ячейкам («Иванов» | «Иван» | «Иванович»), и по
  одной ячейке spaCy не находит сущность.

### Что обходится в офисных форматах

| Формат | Обходится | Не обходится |
|---|---|---|
| `.docx` | абзацы тела, таблицы, верхние и нижние колонтитулы (в т.ч. «чётная» и «первая» страница), таблицы в колонтитулах | текст в картинках, комментарии рецензента, исправления (tracked changes) |
| `.xlsx` | текстовые и числовые ячейки всех листов | формулы, именованные диапазоны, диаграммы, скрытые листы не читаются |
| `.pptx` | текстовые рамки, таблицы на слайдах, группы фигур, заметки докладчика | содержимое диаграмм, SmartArt, заметки в старом формате `.ppt` |

Формулы `.xlsx` лежат отдельным полем и в текст ячейки не входят, поэтому они не
анализируются; если формулы есть, в ответ уходит предупреждение. Если в
формуле зашиты ПДн — они остались в файле.

## API

### Текст

```bash
curl -X POST localhost:8000/api/v1/anonymize/text \
  -H 'Content-Type: application/json' \
  -d '{
    "text": "Паспорт 45 08 123456, ИНН 7707083893. Клиент — Алексей Никитин, a@b.ru",
    "strategy": "placeholder",
    "entities": ["PERSON", "EMAIL_ADDRESS"]
  }'
```

Поля запроса:

| Поле | Значения |
|---|---|
| `strategy` | `placeholder` · `mask` · `redact` · `hash` |
| `entities` | белый список типов массивом, например `["PERSON", "EMAIL_ADDRESS"]`; `null` или `[]` — все |

Ответ содержит `text`, список `findings` (со `source`: `regex` / `presidio` /
`presidio`), `counts`, `elapsed_ms`, `warnings`.

### Файлы

`POST /api/v1/anonymize/file`, multipart-поле `file`.

| Параметр | По умолчанию | Комментарий |
|---|---|---|
| `strategy` | `placeholder` | `mask` · `redact` · `hash` |
| `response_format` | `file` | `file` — сам файл; `json` — отчёт без содержимого |
| `entities` | все | повторяемый query-параметр `?entities=PERSON&entities=EMAIL_ADDRESS`; неизвестное имя → 422 |

```bash
# вернуть файл
curl -s -X POST localhost:8000/api/v1/anonymize/file \
  -F 'file=@договор.docx' -o договор.anonymized.docx -D headers.txt

# отчёт без содержимого документа
curl -s -X POST 'localhost:8000/api/v1/anonymize/file?response_format=json' \
  -F 'file=@клиенты.xlsx' | jq

# PDF отклоняется
curl -X POST localhost:8000/api/v1/anonymize/file -F 'file=@скан.pdf'
# → 400 {"detail":"Формат «.pdf» не поддерживается. Доступны: .txt, ... "}
```

Поддерживаются `.txt` `.md` `.markdown` `.log` `.csv` `.tsv` `.json` `.docx`
`.xlsx` `.pptx`. Формат определяется по расширению: `photo.pdf.exe`
отклоняется с `400`, `a.exe.txt` обрабатывается как `.txt`.

Заголовки ответа: `X-Anon-Filename`, `X-Anon-Found` (сколько находок),
`X-Anon-Units` (сколько блоков разобрано), `X-Anon-Entities`,
`X-Anon-Warnings`, `X-Anon-Elapsed-Ms`. Значения
percent-энкодируются — заголовки HTTP ограничены latin-1, а текст русский.

`Content-Disposition` содержит ASCII-заглушку и `filename*=UTF-8''…`: имя с
кириллицей в заголовок в latin-1 не помещается.

Отчёт в `json` содержит `findings` с **исходными значениями** находок. То есть
сам отчёт — персональные данные; для передачи третьим лицам берите `file`.

### Стратегии

| Стратегия | Пример для ФИО |
|---|---|
| `placeholder` | `[ФИО]` — по умолчанию, читаемо |
| `mask` | `*******` |
| `redact` | пусто |
| `hash` | `[PERSON:9f2a…]` — псевдоним, повторно анонимизируется |

## Что важно знать про файлы

- **Структура документа сохраняется.** В docx и pptx меняется текст абзацев:
  в docx заменяются текстовые XML-узлы с сохранением окружающих run'ов,
  табуляции, рисунков и полей; запись текста проверяется до выдачи файла.
  В pptx оформление заменённого абзаца берётся от первого run'а, поэтому
  смешанное форматирование внутри абзаца может упроститься.
- **Числа с ПДн обнуляются, а не подменяются строкой.** ИНН, записанный
  числом, — тоже персональные данные. Текстовая заглушка изменила бы тип и
  сломала схему данных, поэтому значение становится `0`, а в `warnings` есть
  явное уведомление. Числа без находок не трогаются вообще.
- **JSON сохраняется валидным**: меняются строковые значения и числа с
  находками, ключи, булевы и `null` не трогаются.
- **Кодировки.** Текст читается как `utf-8-sig`, `utf-8`, `cp1251`, `koi8-r`.
  Если файл оказался не в UTF-8, в `warnings` есть предупреждение: часть
  кириллических ПДн могла не распознаться.
- **Невидимые пробелы не мешают поиску.** Word и Excel подставляют неразрывный
  пробел (U+00A0) при переносе строк и выравнивании колонок, поэтому
  «45 08 123456» или «4276 3800 1234 5679» с U+00A0 раньше не находились ни
  одним детектором. Теперь такие пробелы и дефисы считаются разделителями
  групп наравне с обычным пробелом. Замена идёт по исходному тексту, символы
  на месте, включая сам неразрывный пробел.
- **CSV и TSV** обрабатываются как плоский текст — кавычки и переносы строк
  внутри полей не разбираются. Колонки после замены остаются на месте, потому
  что длина строки меняется только значениями.
- **Формат определяется именем, а не содержимым.** `отчёт.pdf` отклонится, даже
  если внутри обычный текст; наоборот, настоящий PDF под именем `a.txt`
  пройдёт как `.txt`, и разбираться будет его двоичный мусор.
- **Лимиты:** 20 МБ на файл, 20 000 текстовых блоков в офисном документе,
  2 000 000 символов текста.

## Важно про `entities`

Неизвестное имя сущности даёт **422**, а не пустой результат:

```json
{"detail": {"error": "unknown_entities", "unknown": ["string"],
            "supported_entities": ["PERSON", "EMAIL_ADDRESS", "..."]}}
```

Это защита от сценария «анонимайзер молча вернул исходный текст из-за опечатки
в фильтре». Дополнительно в ответе есть `warnings` — например, если фильтр
применён, но не нашёл ничего, файл возвращается с явным предупреждением.

Белый список всегда равен тому, что сервис **реально** может найти: regex-детекторы
+ распознаватели presidio. `GET /api/v1/entities` раскладывает его по источникам:

```json
{"regex": ["INN_RU", "..."], "presidio": ["QUANTITY", "..."], "all": ["..."]}
```

Учтите, что `supported_entities` означает «сущность обслуживается», а не
«находится часто». Например, `QUANTITY` доступна как фильтр, но на практике
срабатывает редко — порог `score_threshold` отсекает большинство чисел.

### Как передать `entities`

Формат везде одинаковый — **массив строк**. Различается только место, куда его
класть:

| ручка | как передать фильтр |
|---|---|
| `POST /api/v1/anonymize/text` | поле `entities` в теле: `{"entities": ["PERSON", "EMAIL_ADDRESS"]}` |
| `POST /api/v1/anonymize/file` | повторяющийся query-параметр: `?entities=PERSON&entities=EMAIL_ADDRESS` |

Пробелы внутри элементов и повторы допустимы: `["PERSON", " PERSON "]` и
`["PERSON", "", "  "]` означают один и тот же фильтр. Пустой массив и `null` —
фильтра нет, то есть ищутся все поддерживаемые сущности.

Строка в теле текстовой ручки — прошлый формат, она отклоняется с `422` и
подсказкой, а не принимается молча:

```json
{"detail": [{"loc": ["body", "entities"],
             "msg": "Value error, entities принимается массивом строк, например [\"PERSON\", \"EMAIL_ADDRESS\"], а не строкой «PERSON,EMAIL_ADDRESS»."}]}
```

**Если фильтр не задан, ищутся все поддерживаемые сущности.** Такой дефолт
выбран сознательно: сузить выборку вы всегда можете, а вот не заметить
незамаскированный номер счёта в выданном файле — уже нет.

## Замеры (этот хост, режим `fast`, медиана из 5 прогонов)

Текст:

| Сценарий | Символов | Время | Находок |
|---|---|---|---|
| Короткий контакт | 90 | 10 мс | 4 |
| Паспорт + ИНН + СНИЛС + карта + счёт | 133 | 17 мс | 5 |
| Текст без PII | 74 | 7 мс | 0 |
| Длинный текст (x20) | 4 440 | 182 мс | 100 |

~41 мкс на символ.

Файлы (те же данные, что и в фикстурах тестов, через HTTP):

| Формат | Размер | Время | Находок |
|---|---|---|---|
| `.txt` | 230 Б | 15 мс | 5 |
| `.csv` | 165 Б | 11 мс | 7 |
| `.json` | 177 Б | 12 мс | 4 |
| `.xlsx` | 5.5 КБ | 16 мс | 4 |
| `.pptx` | 28 КБ | 15 мс | 2 |
| `.docx` | 37 КБ | 26 мс | 5 |

Разница с текстом небольшая: время уходит на разбор и запись файла, а не на
детекторы. Объём офисного файла целиком не влияет на скорость — важно число
непустых блоков.

## Что не сделано

- **PDF и сканы.** Формат не принимается; извлечение текста из изображений в
  сервисе тоже нет.
- **Пакетная обработка** (много файлов за раз) и очередь задач.
- **Полная проверка результата повторным разбором готового файла в API.**
  Находки берутся из исходника. Для DOCX проверяется записанный текст абзацев.
- **Снятие метаданных** офисных файлов: автор, компания, время правки в
  свойствах документа остаются.
- **Формулы `.xlsx`, комментарии и исправления `.docx`, диаграммы и SmartArt
  `.pptx`** — не анализируются.
- **Точность spaCy на коротких обрывках.** Отдельный абзац вида «Паспорт
  45 08 123456» без двоеточия может быть размечен как ФИО: подпись к полю
  попадёт под замену вместе с номером. Лишнее закрытие — безопасная сторона
  ошибки, но выглядит в отчёте странно.
- **Короткие аббревиатуры и хим. формулы.** Модель `ru_core_news_sm` считает
  организациями короткие токены в верхнем регистре («ВХОД», «КОФ») и латинские
  формулы («CaCl», «NaOH») — постыдный источник ложных срабатываний. Сервис
  отсекает их по форме слова: короткое слово без признака юрлица («ООО …»,
  «… БАНК») или латинская формула с двумя заглавными буквами не маскируются.
  Стоимость — редкий пропуск настоящей короткой аббревиатуры-организации.

## Запуск

Требуются Docker Engine и Docker Compose v2. Интернет нужен для первой
сборки и загрузки модели; обработка документов выполняется локально.

```bash
cp .env.example .env
docker compose config --quiet
docker compose up -d --build   # первая сборка (или после смены зависимостей)
docker compose up -d           # поднять без пересборки
docker compose logs -f api
```

API содержит spaCy `ru_core_news_sm`; Ollama работает в отдельном контейнере.
Одноразовый `model-init` проверяет наличие Qwen и скачивает её при первом
запуске. Модель сохраняется в томе `ollama_data`.

### Правки кода без пересборки

По умолчанию код находится в образе: после правок нужна пересборка API.
После изменения исходников выполните `docker compose up -d --build api`.

Сборка multistage: тяжёлый слой с зависимостями (uv + spaCy) кешируется по
`requirements.txt` и не пересобирается при правках кода.

## Настройки

Всё через `ANON_`-переменные; часть прокинута в `docker-compose.yml`, остальное
можно задать через `.env` (образец — [`.env.example`](.env.example)).

| Переменная | По умолчанию | Комментарий |
|---|---|---|
| `ANON_SPACY_MODEL` | `ru_core_news_sm` | модель NER; тяжелее — точнее на русском |
| `ANON_MAX_FILE_BYTES` | `20971520` | 20 МБ на файл |
| `ANON_MAX_OFFICE_SEGMENTS` | `20000` | текстовых блоков в офисном документе |
| `ANON_MAX_TEXT_CHARS` | `2000000` | символов текста |
| `ANON_API_WORKERS` | `1` | воркеров uvicorn; память на spaCy — на каждого |
| `ANON_API_KEY` | пусто | ключ для заголовка `X-API-Key`; обязателен в production |
| `ANON_ENV` | `development` | `production` без `ANON_API_KEY` — сервис не стартует |
| `ANON_DOMAIN` | `localhost` | домен для TLS (см. «Деплой как микросервис») |

`ANON_SPACY_MODEL` требует, чтобы модель была скачана в образ: она ставится на
сборке через `python -m spacy download`. Смена на другую модель означает
пересборку образа.

## Деплой как микросервис

Для внешнего HTTP-сервиса включите профиль `tls`: перед FastAPI стоит Caddy
(автоматический Let's Encrypt, rate limit, лимит тела), единственная точка входа —
`443`.

```
[клиенты] → HTTPS:443 → Caddy → HTTP:8000 (внутр. сеть) → api (spaCy)
              TLS + rate limit 30/мин + тело ≤25MB      X-API-Key
```

1. **DNS**: A-запись вашего домена → IP сервера.
2. **Открыть порты** `80` и `443` в firewall (80 нужен для верификации Let's
   Encrypt и редиректа на HTTPS).
3. **`.env`** на сервере:

   ```bash
   cp .env.example .env
   # ANON_DOMAIN=anonymize.example.com
   # ANON_API_KEY=<secrets.token_urlsafe(32)>
   # ANON_ENV=production
   ```

4. **Запуск**:

   ```bash
   docker compose --profile tls up -d --build
   ```

5. **Проверка**:

   ```bash
   curl -fsS https://your.domain/health                    # 200, без ключа
   curl -fsS https://your.domain/api/v1/anonymize/text \
     -H 'Content-Type: application/json' \
     -H 'X-API-Key: ...' \
     -d '{"text": "ИНН 7707083893"}'
   # без ключа → 401 {"detail":"Invalid or missing X-API-Key"}
   ```

Клиент из другого проекта (Python):

```python
import httpx

resp = httpx.post(
    "https://your.domain/api/v1/anonymize/text",
    headers={"X-API-Key": "..."},
    json={"text": "Иван Иванов, +7 912 345-67-89"},
)
print(resp.json()["text"])  # "[ФИО], [ТЕЛЕФОН]"
```

Что защищает наружу: TLS (Caddy), API-ключ (`/api/v1/*` без `X-API-Key` → 401),
rate limit по IP на прокси (по умолчанию 30 req/мин), лимит тела 25 МБ до
попадания в spaCy. `/health` открыт для мониторинга.

## Тесты

```bash
docker compose --profile test build tests
docker compose --profile test run --rm --no-deps tests pytest -q
```

Тесты не ходят в сеть: все файлы генерируются кодом в `tests/file_fixtures.py`.
В production-образ pytest не устанавливается. В тестах Ollama подменяется;
качество реальной модели нужно проверять отдельно через API. В последнем
полном прогоне оставались 16 ошибок API-тестов: формат ответа списка сущностей,
передача фильтра сущностей для файлов и совместимость параметра `mode`.

Локально (без Docker) тесты гоняются так:

```bash
uv venv .venv && uv pip install -r requirements-dev.txt   # или python -m venv + pip
uv run pytest -q
```

## Миграция с прежней версии с LLM

Старый протокол с режимами `balanced`/`deep` не восстановлен. Новый
локальный слой включается отдельно через `ANON_OLLAMA_ENABLED`. Если вы
обновляетесь с прежней версии, где был Ollama:

| было | стало |
|---|---|
| `mode=balanced` / `mode=deep` | → `422` с объяснением; используйте `fast` |
| `ANON_LLM_*`, `ANON_OLLAMA_HOST` | старые настройки игнорируются; используйте новые `ANON_OLLAMA_*` выше |
| старые сервисы `ollama`, `ollama-pull` | новый Compose использует `ollama` + `model-init` и сохраняемый том `ollama_data` |
| `llm_used` в ответе, `/health`, `/stats` | поля убраны |
| `X-Anon-Llm-Used` | заголовок убран |
| `llm` в `GET /api/v1/entities` | ветка убрана |
| `MEDICAL` в фильтре `entities` | → `422`: сущность больше не обслуживается |
| `stats.llm_calls` | счётчика нет |
